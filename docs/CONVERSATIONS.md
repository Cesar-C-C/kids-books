# Codex 会话分工

项目长期使用五类任务。一个任务只处理一类问题；标题统一写成 `[类别] 具体目标`，避免把绘本、3D、配音、Git 和发布混在同一上下文。

每个新任务开始时先阅读 `PROJECT.md`、`docs/STATUS.md` 和本文件，再检查当前 Git 根目录、分支、远端和未提交改动。

当前三份说明文档尚未提交，因此现有五个分类任务直接共享项目目录。将来若改用隔离工作树，必须先确认本地 `main` 存在并跟踪 `origin/main`，且工作树需要读取的说明已经进入 Git 历史；否则会出现 `invalid reference: main`，或新任务只能看到旧版本文档。

## 1. 项目规划与集成

标题示例：`[项目规划与集成] 规划下一季度内容路线`

负责版本路线、目录边界、跨模块接口、优先级和总体验收。一个请求同时涉及两类以上工作时，在这里拆成独立任务；这里不长期承载具体插画生成、模型调试、配音批处理或发布操作。

## 2. 绘本内容与插画

标题示例：`[绘本内容与插画] 制作恐龙灭绝双语绘本`

负责故事分镜、科学解释、双语文案、插画、热点、阅读器页面和单本绘本体验。音频只定义朗读文本与角色需求，具体生成转到“配音与音频”；上线操作转到“测试发布与线上问题”。

## 3. 3D 科普实验室

标题示例：`[3D 科普实验室] 优化火箭分级拆解`

负责 Three.js 模型、材质、装配/拆解、部件知识、相机与触控交互、实验室专项测试。大批量 TTS 转到“配音与音频”；GitHub Pages 故障转到“测试发布与线上问题”。

## 4. 配音与音频

标题示例：`[配音与音频] 完成云朵绘本角色配音`

负责 TTS 服务选择、声线、文本切分、批量生成、格式转换、音频清单、样本质量、播放器接入和降级策略。生成完成后必须与对应绘本或 3D 任务协同做实际入口验证。

## 5. 测试发布与线上问题

标题示例：`[测试发布与线上问题] 发布新版绘本并验证 Pages`

负责静态检查、浏览器回归、PWA/离线、资源引用、Git 状态、提交、PR、GitHub Pages、CDN 和 Service Worker 缓存。提交、推送、合并和发布分别需要明确授权；生成文件存在不能替代主动引用和线上验证。

## 路由规则

- “新做一本绘本并上线”：规划任务拆成“绘本内容与插画”和“测试发布与线上问题”。
- “给 3D 高铁换声音并修播放按钮”：拆成“配音与音频”与“3D 科普实验室”，由后者完成运行时接入验证。
- “图片生成好了为什么线上还是旧图”：进入“测试发布与线上问题”，检查实际引用、构建、PWA、Service Worker 和 CDN。
- 同一类工作的后续问题继续原任务；目标已经变化或跨类时新建任务，不在旧任务里不断追加。
- 任何任务发现跨类依赖时，只记录接口和阻塞条件，把实现交给对应类别。

## 删除旧会话前

确认 `docs/STATUS.md` 已记录当前事项、验证状态和发布基线。旧任务可以删除，但不要删除本项目的 Git 历史、`PROJECT.md`、`docs/STATUS.md` 或 `docs/CONVERSATIONS.md`。
